# Unemployed — сценарий на пять минут

## 0:00–0:30 · Задача

Мы сделали прототип, который принимает видео кассовой операции и возвращает
эпизод для проверки: время, описание и кадр. Весь анализ выполняется локально.

## 0:30–1:15 · Экран загрузки

Здесь пользователь вставляет ключ, выбирает MOV и нажимает «Проверить видео».
Интерфейс показывает ожидание и обработку. Ключ жюри передаём отдельно.
Покажите публичную страницу; ключ и личные данные на экран не выводите.

## 1:15–2:00 · Экран результата

Результат содержит описание и временную метку. Кадр нужен, чтобы человек мог
проверить вывод. На слайде синтетическая демонстрация интерфейса с фигурой;
мы не выдаём её за банковское видео или доказательство точности.

## 2:00–2:45 · API

Сервис доступен и программно: POST принимает файл и возвращает job_id.
GET по этому идентификатору возвращает статус и результат. Есть авторизация,
ограниченная очередь и deadline. Ошибка возвращается как failed.

## 2:45–3:30 · Локальная обработка

Из записи извлекаются кадры по времени; их анализирует локальная Qwen3-VL-4B.
Есть отдельный редактор для ручной проверки фрагментов и сохранения исправлений.
Сохранение исправлений не означает автоматического обучения весов.

## 3:30–4:15 · Проверки

В локальном проекте прошли279тестов. Один HTTP-запрос с настоящей моделью
завершился за87,936с. Проверены JSON, исходный кадр, очередь и восстановление
worker. Скорость одного запроса не является метрикой точности.

## 4:15–5:00 · Ограничения и следующий шаг

Инфраструктура работает; качество распознавания остаётся основной проблемой.
Нужны устойчивые связи участников и предметов, затем независимая проверка.
Текущий детектор не прошёл проверку качества; нормативные основания событий
не подтверждены. Мы показываем работающий прототип и измеренные ограничения.

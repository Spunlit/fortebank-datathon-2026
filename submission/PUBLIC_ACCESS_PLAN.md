# Публичный доступ — подготовлен, не включён

Локальный адрес сервиса: http://127.0.0.1:8000 . Редакторы8800/8801 не публиковать.
Внешняя публикация требует явного подтверждения пользователя; вход в учётную
запись выполняет сам пользователь. Никакие облачные AI API не используются.

Рассмотренный маршрут: Tailscale Funnel. По официальной документации Funnel
ретранслирует зашифрованный трафик, а TLS завершается на устройстве команды;
relay не получает содержимое запросов в открытом виде. Это техническое свойство,
не письменное одобрение решения организаторами хакатона.
Источник: https://tailscale.com/docs/features/tailscale-funnel

Перед включением нужны установленный Tailscale, вход пользователя, MagicDNS,
HTTPS и разрешение Funnel в его tailnet. На момент подготовки Tailscale не установлен.
Команда ниже предназначена только для выполнения ПОСЛЕ подтверждения публикации
и входа пользователя, из PowerShell:

```powershell
& 'C:\Program Files\Tailscale\tailscale.exe' funnel --bg http://127.0.0.1:8000
& 'C:\Program Files\Tailscale\tailscale.exe' funnel status
```

Публикуется только порт8000. API сохраняет X-API-Key; выдавать ключ только жюри.
Не использовать Funnel для каталога workspace и не публиковать local_only.
DNS может потребовать время; документация указывает до10минут. Есть ограничения
пропускной способности: фактическое время загрузки/обработки нужно проверить.
CLI: https://tailscale.com/docs/reference/tailscale-cli/funnel

После включения проверить публичный URL с другого устройства/сети,401без ключа,
готовность с ключом, загрузку безопасного синтетического файла и статусы задач.
Реальные данные отправлять только в подтверждённый сервис команды; не в облачный
чат, просмотрщик или сторонний анализатор. Проверку через облачный браузер-агент
с реальными данными не выполнять.

Отмена опубликованного прокси:
```powershell
& 'C:\Program Files\Tailscale\tailscale.exe' funnel --https=443 off
```

Этот документ не выполняет установку, вход, изменение политик или публикацию.
